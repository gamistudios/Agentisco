The whole loop

From idea to running project

Six steps, one app, no laptop. Every feature below plugs into this flow.

  1. 01

    Bring your project

    Import any folder or ZIP, or start a new one. No template, no rewrite, no special project format.

  2. 02

    Tell the agent

    "Add dark mode and fix the auth bug." Plain language, with the whole project as context.

  3. 03

    Let it work

    It explores, plans, edits files, installs what's missing and runs commands in a real Linux shell.

  4. 04

    Watch everything change

    Live diffs, terminal output and each tool call as it happens — cancel one step, correct course, or edit the file yourself.

  5. 05

    Run and test it

    Install, build, test and run as one pipeline, then open the result in the built-in live preview.

  6. 06

    Ship it

    Review what changed, commit with a message the agent wrote, branch, stash, tag, push and sync.

Working with agents

Don't ask it questions. Hand it the project.

This is the part that makes Awaki feel like a desktop agentic IDE rather than a chatbot: the agent has real tools over your real files and a real shell, and it loops until the work is actually done.

What happens after you press send

  • You: "add rate limiting to the API"
  • ↓ explores the project
  • ↓ draws up a plan you can see
  • ↓ edits the files
  • ↓ installs the dependency it needs
  • ↓ runs the project
  • ↓ reads the error it just hit
  • ↓ fixes it and runs the tests
  • ↓ shows you every change it made

Real edits, not code snippets

It creates, replaces and moves files in your project, and each edit lands as a diff you can read right there in the conversation.

Your shell, its shell

Commands run in the same Linux session you can open and watch — copy the exact command it used, answer a prompt waiting for input, or interrupt it.

You decide how much it may do

Approve each edit and command, or dial it to autonomous. Risky commands are flagged, deletions always ask, and any single step can be cancelled and retried.

Plan mode

Understand a codebase you inherited, answer questions, draft the approach — with a guarantee that nothing gets modified.

Steer it mid-turn

Edit and resend any message, pause or stop a turn, switch to another model when one gets rate-limited, and pick the conversation back up where it stopped.

Remembers, and researches

Sessions persist per project, long conversations are summarised instead of falling off the end, and it can search the web and read pages when it's unsure.

Run it for real

A Linux development machine in your pocket

Awaki ships an Ubuntu userland inside the app — no root, nothing to download on first launch. It's the same environment your agent works in, so whatever runs in the terminal runs for the agent. 

$ apt install nodejs npm
$ npm install
$ npm run dev

$ python3 -m venv .venv
$ .venv/bin/pip install -r requirements.txt

$ go test ./...
$ cargo build --release
$ git status
  • Install anything apt has. Node, Python, Go, Rust, PHP, Ruby — the archive is the normal one, so the CLI apps you already use work here.
  • Interactive terminal, several at once. Real PTY sessions in tabs with a developer key strip for CTRL, ESC, TAB and arrows.
  • Your project, mounted. Every project you open appears in the Linux filesystem, and the files stay there between launches.
  • One environment, two users. You and the agent run the same commands against the same tree — no simulated sandbox.

Live preview

Build it. Run it. See it on your screen.

Start your dev server and the site opens inside Awaki. No tunnel, no second device, no "it works on my machine" — you are looking at the thing you just built.

One-tap pipelines

Install → build → test → run as a sequence that stops at the first failure. Each stage is a command you can edit, and the whole set is detected from your project's own files.

It finds the port for you

Awaki watches the server's own output, works out which port came up, and offers Open preview the moment it answers.

In-app, or in your browser

Reload the preview after every change, or hand the URL to Chrome on the same phone. The dev server keeps serving while you do something else.

Scripts are read from the project as it really is — package.json (npm, pnpm, yarn, bun), Gradle, Cargo, Go, Python and Django, PHP, Ruby, .NET, Maven, Flutter and plain HTML — so a folder you import already has its run buttons.

Source control

Full Git, the way you use it on a desktop

Real git running in the Linux environment, with a screen for each of the things you'd otherwise reach for a laptop to do. The point: see exactly what your agent changed before you commit it.

Changes and diffs

Staged, unstaged, untracked and conflicted files side by side, line-by-line diffs, +/- counts, copy a diff, per-file stage or discard.

Commit, with help

Commit and amend, with a message the agent writes from the actual diff — and an "explain this commit" button when you're reading someone else's history.

Branches

Create, switch, rename and delete, local and remote, with search. feature/auth is two taps away.

Fetch, pull, push, sync

Each one a button, plus a single Sync that pulls and pushes. Add, rename and remove remotes as you like.

History

Paginated log with per-file stats, commit details, revert, cherry-pick, reset with soft/mixed/hard warnings, merge and rebase with abort and continue.

Stashes and tags

Park work with untracked files included, then apply, pop or drop it. Create annotated tags, delete them, push them.

Conflicts, handled

Conflicted files are listed and open straight into the editor to resolve, then continue the merge — or back out cleanly.

Agent-driven Git

The agent stages, commits and reads history through the same commands, and you review what it did as a diff — not as a claim.

Stuck? Unclog it

A leftover index.lock offers a one-tap remove instead of a stack trace, and history reloads itself after operations that rewrite it.

Background work

Start the work. Put the phone away.

A long agent turn shouldn't need an audience. Awaki keeps the work alive when you leave the app, so the phone goes back in your pocket while the install, the build or the refactor carries on.

Keeps running off-screen

  • · Agent sessions and their tool calls
  • · Builds, tests and long-running commands
  • · Dev servers you're previewing
  • · App downloads

A notification shows what's running, and it pulls you back with an alert when the agent needs your approval or the run was interrupted.

Set up once in Settings

A checklist shows what background work needs on your device — notifications, battery optimisation, keeping the terminal awake — each with a button that opens the right system screen.

Come back and the transcript is where you left it, with every step it took while you were gone.

Any project

Already have code? Bring it.

Awaki doesn't ask you to start from a template or move into its own format. Give it the folder, and the agent works on that project the way it is.

Import a folder

Pick any directory on your device. Changes can be mirrored back to where it came from.

Import a ZIP

A download, an archive from your mail, a backup — unpack it into a project and start.

Clone git repository

You can use the built in terminal to clone any repository just as if you're using Ubuntu Desktop environment.

Start fresh

A new empty project is enough: the agent can scaffold, install and run from there.

Knows what it is

Real size, last edit, project type and icon detected from the files, plus ignore rules so node_modules doesn't slow everything down.

Conversations, open tabs and the project you were last in are all still there the next time you open the app.

Editor

And when you want to type it yourself

An editor good enough to live in: multiple tabs, syntax highlighting for 26 languages and five themes, symbol outline, go-to-line, find & replace with match-case and whole-word, full undo and redo, word wrap and bracket matching. Images and SVGs preview instead of dumping text on you. Select a block, tap Ask Agent, and it answers about that code.
